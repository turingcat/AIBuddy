# HeyBuddy 桌面端输入区与侧栏交互优化设计

## 目标

优化 HeyBuddy 桌面端输入区和左侧栏的视觉一致性与操作效率：统一新对话和已有会话的输入框宽度，修正附件按钮排版，将余额刷新入口合并到账号菜单头部，并按会话状态显示删除按钮。

## 范围

本次改动仅涉及桌面端现有组件的布局、样式和交互，不修改聊天提交、附件选择、余额查询、会话删除或 ACP 通信的业务逻辑。

## 输入区布局

- 新对话页输入区最大宽度从 `max-w-3xl` 调整为 `max-w-4xl`，保持水平居中。
- 已有会话底部输入区使用相同的 `max-w-4xl` 最大宽度和响应式左右留白，保持水平居中并固定在现有底部位置。
- 窄窗口下输入区继续缩小到可用宽度，不产生水平滚动或覆盖侧栏。
- 两种会话状态继续复用 `ChatInputCard` 和 `ChatInput`，不创建第二套输入组件。

## 附件与发送按钮

- 附件按钮从固定圆形尺寸改为适合图标加文字的 pill 尺寸，避免文字溢出按钮布局宽度。
- “附件”文字使用 `text-xs`，与“目录”“上下文”“扩展”等工具栏提示保持一致。
- 附件按钮与发送按钮之间保留约 12px 的视觉间距；其他工具栏项目仍使用现有紧凑间距。
- 窄工具栏仍隐藏“附件”文字和次要控件，保留当前模型与发送按钮的响应式规则。

## 账号菜单与余额刷新

- 弹出菜单头部改为单行布局，依次容纳用户图标、用户名、余额和刷新图标。
- 用户名优先使用 `display_name`，为空时使用 `name`，两者均为空时沿用未登录提示。
- 刷新图标调用现有 `useBalance().refresh()`，刷新期间使用旋转状态，并保留可访问名称和提示。
- 删除独立的“刷新余额”菜单项；“设置”和“退出登录”继续作为菜单命令。
- 刷新失败时沿用现有 `useBalance` 状态和 `BalanceStatus` 提示，不新增重复的错误处理。

## 会话删除按钮

- 当前高亮会话的删除按钮始终可见。
- 非当前会话的删除按钮默认透明且不可被鼠标误点，在会话行悬停或键盘焦点进入该行时显示。
- 删除按钮继续保留可访问名称、阻止行点击冒泡，并沿用现有确认弹窗、ACP 删除、本地快照清理和列表刷新逻辑。
- 会话标题继续单行截断，删除按钮出现时不得挤出侧栏或引起行高变化。

## 测试与验证

- `ChatInput` 测试验证附件按钮使用与其他工具一致的文字尺寸，并具有独立于发送按钮的间距和自然宽度。
- `Hub` 与 `BaseChat` 测试验证两种状态使用相同的最大宽度且水平居中。
- `UserAccountMenu` 测试验证用户名与余额同排、独立“刷新余额”菜单项消失、刷新图标调用共享刷新函数并展示加载状态。
- `NavigationPanel` 测试验证非当前会话默认隐藏、悬停或聚焦显示、当前会话常显，并确认原删除流程不回归。
- 运行桌面端相关单测、全量 UI 测试和 TypeScript typecheck。
- 在桌面宽屏视口检查新对话页和已有会话页截图，确认输入区宽度一致、居中且控件无重叠。

## 非目标

- 不改变输入区高度、圆角、颜色或消息队列行为。
- 不改变余额计算、轮询周期、货币格式或登录协议。
- 不改变会话删除确认文案或删除数据流程。
- 不调整移动端或窄工具栏中现有的控件取舍。
